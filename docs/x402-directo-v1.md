- Estado de partida observado: produção `af7a0be` (= main, deployment `dpl_3WTMJdzEsKsUrKK7fE7DjqhMqg6Q` READY, `/api/versao` 200). `/x402` e `/licenca` respondiam 503 `upstream_payment_unavailable`: as Edge Functions Supabase continuam fora de quota de egress (ora_mudancas #764–#771). Nenhum serviço pago recebia.
- `api/_x402-directo.js`: quando o Supabase falha (402 sem desafio, 5xx ou rede), o proxy serve directamente no Vercel os dois serviços que não precisam de base de dados — `/oraculo` (0.161 USDC) e `/campo` (0.33 USDC) — mais as amostras `/oraculo/eco`, `/x402/eco` e o manifesto `/.well-known/x402.json`. Desafio x402 v2 com `PAYMENT-REQUIRED`; prova por `transactionHash`; verificação por RPC Base público (recibo com sucesso, log Transfer USDC para `0xFEd6…DEe5`, valor ≥ preço, bloco com menos de 72 h). Cabeçalho `x-ora-via: vercel-directa`.
- Fronteiras: sem facilitador CDP (EIP-3009 recusado nesta via); sem livro de tx consumidas fora do Supabase — a leitura é determinística por tx (repetir = reacesso) e a janela de 72 h limita a reutilização; nada é escrito em `ora_pagamentos`/`x402_orders` (reconciliar a partir dos logs on-chain quando houver pagamentos). Uma tx usada aqui pode ainda ser aceite uma vez pela Edge quando o Supabase voltar. Sedimento, kernel, licenças e auditoria continuam dependentes do Supabase.
- `api/a2a.js`: nova resposta gratuita (tópico `x402`) que indica a outro agente os serviços pagos vivos no gateway e como pagar; não processa pagamentos nem afirma compras.

Aceitar esses clientes exige decisão de Unum sobre usar a chave CDP (já no Vault) fora do Supabase; a via directa recusa EIP-3009 até lá.
